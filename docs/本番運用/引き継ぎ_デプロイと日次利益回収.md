## 3. フロント / JSON の正本

| ファイル | 用途 |
|----------|------|
| `frontend/src/lib/contracts/deployments/999.json` | アプリ + cron が読む本番設定 |
| `contracts/deployments/999.json` | スクリプト側コピー（**常にフロントと同期**） |
| Vercel プロジェクト | **`hyper-evm` のみ**（新規 `frontend` プロジェクトを作らない） |

構造:

- **トップレベル** = legacy HYPE/USDC（Cashdrop 状態もここ）
- **`pools[]`** = HYPE建て各ペア。Cashdrop は `pools[i].cashdrop` に隔離

`POOL_KEY` 付き daily-rewards は **自分の `pools[].cashdrop` だけ**書き戻す。  
`POOL_KEY` なし実行はトップレベルを触る → **HYPE建て用に `POOL_KEY` なしで回さないこと。**

## 4. 日次の利益回収（別マシンが実行）

### 4.1 何をするか

1. **harvest** — Vault の LP 手数料を回収し、7% ops / 60% ユーザー枠 / 33% owner に分配。ユーザー枠は `pendingUserRewards` に積む  
2. **distribute** — 株主比率で Merkle を組み、`MerkleAirdrop` 経由で **報酬トークンを自動送金**  
   - legacy: **USDC**  
   - HYPE建て: **WHYPE**  
3. **keeper（6h）** — LP レンジを現在価格中心に recenter + idle を deploy  

スクリプト（ロジックの二重実装禁止）:

- `scripts/daily-rewards.mjs`（`DAILY_REWARDS_PHASE=harvest|distribute`）
- `scripts/keeper-rebalance.mjs`
- ラッパー: `scripts/cron/run-daily-harvest-*.sh` / `run-daily-distribute-*.sh` / `run-keeper-*.sh`

### 4.2 運用マシンに必要なもの

| 項目 | 値 |
|------|-----|
| リポジトリ | `main` を pull した作業コピー |
| 秘密鍵 | `MAIN_PRIVATE_KEY`（ウォレット `0x0196…8ceC`）。**git に入れない** |
| Chain | `DEPLOYMENT_CHAIN=999` |
| Node | 20+、`frontend/node_modules/viem` あり |
| git push | distribute 成功後に両 `999.json` を commit/push（Cashdrop UI 更新用） |

セットアップ手順:

- Windows Server + WSL2 → [windows-server-wsl2-cron.md](./windows-server-wsl2-cron.md)
- Linux VPS → [vps-cron.md](./vps-cron.md)
- マシン分担の概要 → [cron-運用マシン.md](./cron-運用マシン.md)

### 4.3 crontab（HYPE建て・必須）

テンプレ全文: `scripts/cron/hyperpool.example.crontab`  
インストーラ例: `./scripts/cron/install-vps-crontab.sh`（デフォルトで HYPE建てのみ。legacy は入れない）

| JST | 処理 | env |
|-----|------|-----|
| 7:10 / 9:10 / 9:40 | harvest / distribute / retry | `POOL_KEY=upump-whype` |
| 7:20 / 9:20 / 9:50 | 同上 | `POOL_KEY=ubtc-whype` |
| 7:30 / 9:30 / 10:00 | 同上 | `POOL_KEY=ueth-whype` |
| 毎 6h :15 / :30 / :45 | keeper | 各 `POOL_KEY` + `SKIP_ORACLE=1` |

手動 1 回テスト（運用マシン上）:

```bash
cd /path/to/hyper_evm
export DEPLOYMENT_CHAIN=999
export POOL_KEY=ueth-whype   # または ubtc-whype / upump-whype
export SKIP_ORACLE=1         # keeper 時

# 鍵は /etc/hyperpool/env や .env.testnet から load（中身をチャットに出さない）
node scripts/keeper-rebalance.mjs
DAILY_REWARDS_PHASE=harvest    node scripts/daily-rewards.mjs
DAILY_REWARDS_PHASE=distribute node scripts/daily-rewards.mjs
```

### 4.4 Legacy HYPE/USDC の日次回収

- **現状:** デフォルト cron には **含めていない**（明示判断が必要）
- 再開する場合のみ `INSTALL_LEGACY_HYPE_USDC_CRON=1` かつ **`POOL_KEY` なし**
- 報酬 = USDC、トップレベル JSON を更新

### 4.5 やってはいけないこと

| 禁止 | 理由 |
|------|------|
| 開発 Mac と運用マシンで同時 cron | JSON 競合・二重 harvest |
| HYPE建てジョブを `POOL_KEY` なしで実行 | legacy Cashdrop を壊す |
| `finalize-deployment.mjs` を `--pair` なしで 999 に実行 | `pools[]` が消える可能性 |
| 稼働中 gen9 に `setPool` / pause 等 | 既存ユーザー資金に影響 |
| Vercel に無関係な新規プロジェクト作成 | 本番 URL が更新されない |
